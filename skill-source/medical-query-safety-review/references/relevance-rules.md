# 三段相关性与商品事实规则

机器政策 ID：`BRAND-001`、`FORM-001`、`PACK-001`、`AUDIENCE-001`、`EVIDENCE-001`。本文件的 `REL-*` 是对这些稳定约束在三段关系中的执行细则，不新增阈值。

## 三段关系必须分开

1. **Query—term**：候选是否保留原始表达的明确约束，且有标准化依据和索引事实。
2. **term—商品**：索引返回的候选商品是否与 term 的品牌、名称、剂型、包装和人群属性一致。
3. **原 Query—商品**：商品是否满足用户原始意图；不能只因 term 字符串相似就跳过终审。

## 规则

| Rule ID | 适用对象 | 处理要求 |
| --- | --- | --- |
| `REL-001` | 三段关系 | 每一段单独记录结论、理由和证据；不能用上一段的 `pass` 自动推导下一段 |
| `REL-002` | 明确属性 | 品牌、名称、剂型、包装数量/单位和人群按结构化事实核对；结构化字段缺失时保持未知 |
| `REL-003` | 属性冲突 | 标题与结构化属性冲突、不同来源版本冲突或单位无法比较时标记 `unknown` 并进入人工复核，不选择对放行更有利的一侧 |
| `REL-004` | 标题证据 | 标题包含关键词只能作为线索，不能单独证明 SKU 规格、资质或人群相关 |
| `REL-005` | 当前承接 | 供给、地域、商品/商家资格、计划、预算和素材是独立事实；当前不可投不等于改写错误，语义相关也不等于当前可投 |
| `REL-006` | 语义判断 | agent 负责复杂语义相关性；脚本只检查可确定字段冲突、引用和资格规则结果，不能由关键词相同代替审核 |

商品、门店和计划的原始对象应尽量保留在 evidence 中，并用 `candidate_id`、`term_id`、`sku_id`、`offer_id`、`store_id` 建立关系。单个候选失败时隔离该候选，公共数据源失败时阻断所有依赖该源的结论。
