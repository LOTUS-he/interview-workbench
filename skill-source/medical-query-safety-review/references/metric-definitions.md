# 指标与历史证据口径

## 时间与粒度

- 时间均为带 `+08:00` 偏移的 ISO8601 字符串；历史窗口为左闭右开 `[history_start, history_end_exclusive)`。
- `search_requests` 一行对应一个 `request_id`；有效请求只统计 `is_valid=1` 且落在任务窗口、城市、区域、场域内的不同请求。
- `recall_events` 是候选阶段事件，可能重复投递；统计前按业务 `event_id` 去重，再回到 request 粒度。
- 一条请求可以关联多个候选、多个阶段事件或多条历史回放；不能直接对明细行计数代替请求数。

## 指标定义

| 指标 ID | 定义 | 使用注意 |
| --- | --- | --- |
| `METRIC-001` | 有效请求数 = 过滤范围内不同 `request_id` 数 | 分母为 0 时写不适用，不显示 100% |
| `METRIC-002` | 精准召回覆盖率 = 至少有一个合格精准候选的有效请求数 ÷ 有效请求数 | 合格以已确认的阶段事实为准 |
| `METRIC-003` | 无合格候选比例 = 明确无合格候选的有效请求数 ÷ 有效请求数 | 未知请求不能强行归入无候选 |
| `METRIC-004` | 关键词匹配缺口 = 经过独立回放并且有唯一历史资格证明的请求数 | 只是未经语义复核的潜在机会，不是曝光或收入 |
| `METRIC-005` | 曝光次数 = 去重后的 `impression` 业务事件数 | 不能从请求数推断曝光 |
| `METRIC-006` | CTR = 去重后的 click 事件数 ÷ 去重后的 impression 事件数 | 需要明确事件去重和范围 |
| `METRIC-007` | 有效计费 CPC = `billable=1` 的 `spend_fen` 合计 ÷ 对应点击数 | 单位为分；本数据不代表财务收入 |

## 请求级阶段归类

先确定每条有效请求是否存在至少一个可确认的合格候选；只有确定无合格候选的请求，才按既定阶段顺序归类为 keyword、supply、plan 或 unknown。不能因为某一个候选缺货就把整条请求归为供给失败，也不能把缺少历史快照、回放或加载分区的请求当成 0。

`verified_gap_count` 必须由独立历史候选回放、有效时间区间和唯一资格证明共同支持。它应带 `evidence_rows` 供逐 term 复核；不能由今天的 API 快照或模型判断替代。完整性由加载清单、窗口覆盖、请求级对账和资格连接唯一性共同决定。

## 数据质量规则

- 分子、分母和有效样本数一起记录；分母为零或数据不完整时结论为不适用或未确认。
- `NULL`、缺失、过期和工具失败保持不同来源；不能通过 `COALESCE` 或默认值把它们变成业务通过。
- 历史资格使用 `[valid_from, valid_to)` 区间连接；当前 API 快照不能替代历史状态。
