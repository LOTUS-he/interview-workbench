# 审批建议与价值分层政策

本文件解释如何把已完成的审核事实组织成建议；不重复定义资格字段、资格数值或时效阈值。所有资格判断引用 `eligibility-rules.yaml` 的 rule ID。

机器政策 ID：`DECISION-001` 约束入池/hold/reject/no_rewrite 的决策边界，`VALUE-001` 约束商业价值分层必须有完整统计和资格依据；本文件的 `DEC-*` 是解释性细则。

| Rule ID | 决策要求 |
| --- | --- |
| `DEC-001` | 分别给出 Query 准入、Query—term、term—商品、原 Query—商品、当前承接和商业价值结论，不合并成单一“通过” |
| `DEC-002` | 只有风险允许继续、映射语义有依据、历史缺口达到适用审批要求且至少存在一项当前确认可承接供给时，才可给出 `submit_for_human_review`；人工审批和发布仍由有权限人员执行 |
| `DEC-003` | 任一必要证据未知、冲突、过期或失败时，给出 `hold` 或把对象放入 `review_queue`，说明补证路径；不得用文案改写修复事实缺口 |
| `DEC-004` | 高风险或明确冲突给 `reject`；无合理候选给 `no_rewrite`；不能用商业价值覆盖安全红线 |
| `DEC-005` | 商业价值等级只能来自同一 Query、城市、场域和适用历史窗口的完整统计及当前合格门店事实；数据不完整或资格未知时不作确定分层 |
| `DEC-006` | 当前检查时点的资格只支撑当前时点建议；库存变化、计划变化或证据过期时更新资格结论，不自动改写已核验的语义结论 |
| `DEC-007` | 任何建议都必须保留规则和 evidence 引用，且引用的对象属于同一 run；没有引用的自然语言结论不能进入最终报告 |

## 建议枚举

- `submit_for_human_review`：材料满足适用政策，可以交给人工审批；不是发布指令。
- `hold`：存在待补证、冲突或外部审批条件，暂不提交放行。
- `reject`：命中高风险、明确属性冲突或范围不适用。
- `no_rewrite`：没有保留原意且有索引证据的候选；不等于接口失败。

分层和灰度配置若缺少业务方批准口径，报告只列待确认项，不自行选择比例、门槛或实验方案。
